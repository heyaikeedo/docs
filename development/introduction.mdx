Aikeedo is a self-hosted PHP application, and you get its full source code. This section is for developers who want to extend an installation, change how it looks, integrate it with other systems, or understand how the core works before changing it.

## Choose where to start

<Steps>
  <Step title="Set up a local environment">
    Install Aikeedo locally, then follow [Local development](/development/local-development) to turn on debug mode, frontend hot reloading and cron.
  </Step>
  <Step title="Pick the right extension mechanism">
    Read [Extending Aikeedo](/development/extending-aikeedo) to decide between a plugin, a theme and a view override, and to see which changes survive updates.
  </Step>
  <Step title="Build something">
    Follow the [plugin quickstart](/development/plugins/quickstart) or the [theme quickstart](/development/themes/quickstart). Both take you from an empty directory to working code in an installation.
  </Step>
</Steps>

## Technology at a glance

| Layer | Technology |
| --- | --- |
| Language | PHP 8.2+ with `intl`, `gd` and `bcmath` |
| Application framework | Lightweight PSR components from the [`iziphp`](https://github.com/iziphp) packages (`Easy\*`): [DI container](https://github.com/iziphp/container), [attribute router](https://github.com/iziphp/router), [PSR-14 events](https://github.com/iziphp/event-dispatcher), [PSR-15 middleware](https://github.com/iziphp/http-server-handler) |
| Persistence | Doctrine ORM 3 and Doctrine Migrations on MySQL, with binary UUIDv7 identifiers |
| Views | Twig 3 with gettext translation functions |
| Frontend | Alpine.js 3, Tailwind CSS 4 and Vite 8 for the app and admin panel |
| Themes | Twig, Alpine.js, Tailwind CSS 3 and Vite 5 in the official starter kit |
| Tooling | Symfony Console, Composer, PHPStan, PHP_CodeSniffer, PHPMD, PHPUnit |

See [Core architecture](/development/core/overview) for the full picture.

## Conventions in these docs

- **Paths** are relative to the Aikeedo installation root, the directory that contains `composer.json`, `bin/` and `src/`. The web root is `public/` by default, or whatever the `PUBLIC_DIR` environment variable names.
- **Class names** are fully qualified. Core classes have no vendor prefix; for example, `Billing\Infrastructure\Payments\PaymentGatewayInterface` lives in `src/Billing/Infrastructure/Payments/PaymentGatewayInterface.php`.
- **Examples** use a fictional vendor, `acme`, with packages such as `acme/hello` and the namespace `Acme\Hello\`. Replace them with your own vendor and package names.
- **Commands** run from the installation root unless a page says otherwise, for example `php bin/console app:locale:extract`.

## Prerequisites

To follow the guides, you should be comfortable with:

- Modern PHP: namespaces, attributes, enums, readonly properties and Composer
- Twig templates and basic Alpine.js
- Working in a terminal with `php`, `composer` and `npm`

<Note>
  Develop and test extensions on a local or staging copy, not on your production installation.
</Note>
